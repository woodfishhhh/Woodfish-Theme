## 1. 痛点排序（按反馈量）

### P0 · 关不掉 / 卸载后残留（反馈最多）

**B 站约 15 条一级评论 + 若干回复，GitHub #29（开启）、#11、#9、#5。**

典型原话：
- 「卸载后还有，好难受」「那个光标和病毒一样」「我直接把 vscode 卸了」
- 「为啥我取消安装还有彩色字体？」（2026-05，已是集成注入器版本之后）
- 「为什么发光关闭后还在发光」「关闭辉光后，仍然有些是有辉光的（橙色，"方法"）」
- 「彻底关闭也还在」(#11)、「删除清不干净啊」(#29，2026 年仍开启)

代码现状核对：
- `package.json` **没有 `vscode:uninstall` 钩子**。扩展被卸载时 `workbench.html` 里的注入不会被还原，这是「卸载后还在」的直接原因。
- 作者在评论区给的解法是「先关掉字体，再卸载」，等于把正确顺序的负担推给用户。
- 历史上 Custom CSS and JS Loader 时代留下的 `vscode_custom_css.imports` 残留，社区靠「去 settings.json 删行」自救。

### P0 · 升级 VS Code 后失效 / 跟视频操作无效果

**B 站约 13 条，GitHub #10、#14。**

- 「昨天 vscode 更新之后发光失效了」「新版本 vs 失效哩」（作者回复）
- 「照着教程但是字体不发光」「光标不是彩色的也没有动画，那三个插件都下载了」
- 「主题只改变了颜色和背景」「就连颜色都还是原来的黑色」
- #14：日志显示已 `Applied integrated runtime`，但需要**完全重启**才生效 —— 提示文案或流程没讲清「重载窗口」和「重启进程」的区别。
- **教程视频已过时**：视频仍教 Custom CSS and JS Loader + Vscode Animations 三件套，作者 2026-04-07 起反复置顶「后面会出一个新的视频介绍使用方法」，目前 UP 空间里没有新视频。

### P1 · 环境兼容

| 场景 | 反馈 | 现状 / 判断 |
|---|---|---|
| Remote SSH | 「提示找不到 workbench.html，不支持」(2026-06) | `package.json` 未声明 `extensionKind`，远程时扩展跑在服务器端，找不到本地 workbench。声明 `"extensionKind": ["ui"]` 即可修 |
| WSL | 「连接了 wsl 的 vscode 里用不了？」 | 同上 |
| Linux / Ubuntu | 「报错了」「对 Linux 支持不是很好」 | 多为安装目录无写权限（snap / 系统包），需要明确的权限错误提示 |
| Cursor | `EPERM: operation not permitted ... cursor\...\workbench.html`；作者回复「加 todo 了」 | 权限问题 + 未在支持范围内声明 |
| Jupyter | 「jupyter 文件中鼠标拖尾不起作用」 | notebook cell 编辑器的 DOM 选择器未覆盖 |
| 小地图 | 「右上角缩略图中代码的颜色没有变」 | minimap 是 canvas，CSS 无法渐变，属于已知限制，需写进文档 |
| JetBrains Mono | C++ 关键字被裁剪 | 疑似 `background-clip: text` / `text-shadow` 与字形外扩冲突 |
| 「Code 安装似乎损坏」 | 多人询问 | 修改 workbench 后的校验和提示，属预期行为，需在首次启用时说明 |
| CodeSnap、Minecraft Color Highlighter (#15) | 颜色被渐变覆盖 | 作者已回复不兼容。Minecraft 这类插件用 decoration 的行内 `color`，可尝试在渐变选择器里排除带行内颜色的 span |

## 3. 进行中的工作：PR #28（6.0.0 beta）

PR #28「universal theme overlay」已经是一版重构方向，并取代 #26 / #27：

- 把 Woodfish 6 变成**默认开启的覆盖层**，可以叠加在任意 VS Code 配色主题上
- 不再依赖固定的 `mtkN` 编号（这是 Monaco 内部颜色表的索引，主题或配置一变就会错位），改为读取每个 token 的实际计算颜色，在 OKLCH 色彩空间里推导渐变（色相 ±24°、亮度 ±0.060）
- 白色和灰色 token 从主题里取强调色，标点用较弱的发光
- 内置的 Bearded Theme Arc 和 Dracula JSON 恢复成上游原版，并附上许可证

这个方向直接回应了 §1 里的「语义区分度」「颜色和主题对不上」，也让 #16 浅色主题、#4 语言专属优化可以变成「选一个配色主题 + 覆盖层」，不必再逐个手写主题。

## 4. 对重构的建议（按优先级）

1. **卸载即还原**：加上 `vscode:uninstall` 脚本，离线还原 workbench；同时检测并清理 Custom CSS Loader 时代的旧 imports。解决 #29 和最集中的抱怨。
2. **声明 `extensionKind: ["ui"]`**：修复 Remote SSH / WSL。
3. **写不进去时说清楚原因**：EPERM、只读安装（snap、Cursor、系统目录）给出明确的中文提示和处理步骤，而不是只报失败。
4. **以 PR #28 的覆盖层架构为主线**：一次性兑现「更多变体 / 纯黑 / 浅色 / 语言区分度」，把画过的饼收敛成「任意主题 + Woodfish 覆盖层」。
5. **明确收回不做的**：CLion、Visual Studio、CodeSnap、minimap，写进 README 的「已知限制」。
6. **毛玻璃**：要么带开关和透明度重新做，要么在 CHANGELOG 和评论区说明已移除。
7. **更新教程**：重构发布后出新视频，并把置顶评论换成新版操作步骤。
